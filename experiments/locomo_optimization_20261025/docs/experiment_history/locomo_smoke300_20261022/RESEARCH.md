# TiMem 论文与本地实现检查

论文：[TiMem, arXiv:2601.02845v2](https://arxiv.org/html/2601.02845v2)。阅读版本为 2026-04-30 修订稿。

论文核心是带时间包含关系的五层树、逐层记忆整合，以及按问题复杂度规划、传播和筛选的检索流程。第 4.6 节的粒度实验值得优先关注：L1 从 1 轮扩大到 8 轮时，LoCoMo 准确率从 75.30% 降到 65.26%。论文同时指出高层摘要不能替代细粒度事实。其表 1 使用 1,540 题，模型、嵌入和检索预算也与本地不同，因此不能把论文分数直接当成本地 861 题的基线。

## 本地发现

1. AML 输入按最多 20 条消息/2,000 词切块，而不是按会话日期切分。299 块中有 236 块跨越不同时间戳。`EngineMemoryService.message_timestamp` 取首条时间；`stamp_temporal` 又按记忆窗口开始时间解析整篇摘要里的相对日期。这破坏了事件与其原始时间的对应关系。
2. 已有错误实例：5 月 25 日提到的“上周六慈善跑步”被写入 5 月 8 日开始的摘要，错误标成 5 月 6 日。原文时间应支持 5 月 20 日。该问题发生在记忆内容中，单纯增加检索条数无法修复。
3. 多跳错题存在细节丢失，例如只答出一个音乐演出者，或只保留某人的一方面经历。需要可追溯到原句和相邻问答的证据链。
4. 当前第二跳把原问题替换成高频实体，容易扩大到同一人物的无关事件；refiner 模板缺失、ID 格式校验失败又会削弱筛选。这些是后续独立实验方向。

## 本轮修改：可追溯的原文事实叶

- Add 将原始消息、原始角色、原始时间戳、用户/会话/请求及消息位置写入一个持久化 FTS5 索引。没有可用时间时明确保留 unknown，不借用邻条时间。
- Search 在原有 TiMem 检索结果基础上，用原问题检索原文，取同一用户、同一会话、同一时间戳的相邻问答补齐指代和细节。最多 20 个窗口、80,000 字符；保留源消息 ID。
- 时间问题使用原始时间证据，避免已错误换算的摘要日期与原文冲突。其他问题额外保留前 4 条原有摘要作语义上下文；原文无匹配时回退原检索结果。
- 默认开启；`TIMEM_SOURCE_EVIDENCE=0` 可回退。新索引仅接收 Add 内容，检索代码不读取数据集、题目标签、金标或官方证据。
- 当前 299 个历史请求通过迁移脚本补录；原有摘要、向量和上层树不重新生成。本次收益因此针对检索与证据呈现，尚不能代表重新构建整棵树的收益。

## 其他优化方向（本轮未混入）

1. 将 L1 的摘要边界限制在同一会话时间内，保留源句 ID 和事件时间/陈述时间两个字段；之后重建摘要与向量，避免旧错误日期继续传播。
2. 把多跳问题拆成多个保留关系约束的子查询，按不同事实的覆盖率选择证据；用来源 ID 去重而不是按高频人名扩展。
3. 修复 refiner 模板和整数 ID 输出契约，再测试保留桥接事实的策略，记录筛掉正确证据的比例。
4. 在 L1 事实与日期可靠后，试验 L3/L4 的跨事件关联，并要求每个高层结论能够回溯到低层来源。

## 300 题协议（评测前固定）

范围：LoCoMo-Refined，10 段对话；时间 100、多跳 77、单跳 98、推理 25，共 300。类别内按 `sha256('timem-smoke300-v1:' + question_id)` 选取；不按旧判分挑题。包括全部 77 道多跳题，属于开发 smoke 而非独立保留测试集。

两组都使用 `deepseek-v4.1-flash` 答题和判分、temperature=0，保持 benchmark 原有提示和判分规则。基线重新调用当前原始服务获取候选；实验组复用同题这一次候选，再执行与生产模块相同的 `ground_evidence`。这是一轮成对的检索后处理消融，控制了内部检索随机性；不是两次独立的端到端重跑。每组 300 次答题/判分，共 600 条结果。

输入仍是 `f1022b` 的同一批历史会话，其摘要由旧模型生成；两组共享此条件。历史 74.91% 混合模型全量结果只作背景，不用来计算本轮收益。报告除准确率外，还统计错转对/对转错、证据长度、空检索和解析错误。

局限：一次 smoke 存在答题/判分随机性；定向类别比例意味着总分不是全量预估。源码语言索引以英语 stemming 为主。新增原文保留需要纳入正式的数据删除/备份生命周期；本轮在 AML 测试接口范围实现。
