# R1.2 支持原子、替换控制与候选公平性复核

日期：2026-10-24。性质：只读代码审查及离线反例；未调用模型、未访问网络、未修改既有结果。本文件为独立复核记录。

## 1. 结论

当前不能把“六项控制全部通过”解释为已验证安全替换，也不能据 7 次筛选断言瓶颈仅在候选质量。真实候选确有相关性不足的迹象，但支持原子、替换分支和 H 候选去重仍存在可直接复现的问题。

## 2. 六项控制中哪些没有验证其声称行为

| 控制 | 实际执行 | 代码位置 | 应如何修正 |
|---|---|---|---|
| 新答案值接受 | 1 个窗口追加到 2 个，能证明有空间时追加 | `controls.py:25–35` | 保留，并增加满容量下的新值替换测试 |

## 3. 支持集合不能作为当前信息无损证明

`support_atoms.py:44–45` 的 key 只保留 kind/relation/subjects/values，丢弃 conv 与 observed_at。`subjects` 是全文大写单词集合（第 52 行），没有主语、宾语或推荐对象的角色。relation 是第一个白名单动词（第 53 行），values 仅数字和大写短语（第 59–65 行），不覆盖多数小写答案值、否定、计划与事实差别。时间原子仅为常量 `("time",)`（第 67–68 行）。因此所谓 loss=0 只是这组粗糙投影无损。

下列四组反例已实际执行，支持集合分别完全相同：

1. 同文 `Jolene visited Paris.`，observed_at 分别为 2023-05-01 与 2023-06-01。
2. `Jolene recommended Zelda.` 与 `Jolene never recommended Zelda.`。
3. `Caroline enjoys running.` 与 `Caroline enjoys swimming.`。
4. `Jolene recommended Zelda to Deborah.` 与 `Deborah recommended Zelda to Jolene.`。

另外，YEAR 正则中的捕获组使 `YEAR.findall` 返回 `19`/`20` 前缀，而不是完整年份（第 18、59 行）；完整年份仍会被 NUMBER 找到，但多出无意义前缀支持，应改为非捕获组。

关系目前参与 atom 的 equality key，并未参与 query—candidate 关系匹配。选择函数签名没有 query（第 80 行）；模型的 direct/bridge 判决来自前置筛选，不等同于该函数已经实现结构化事件匹配。

满容量时，第 108–111 行要求受害窗口的所有全局原子均由其他窗口/新候选覆盖，连与问题无关的独有事实也必须保留。这种保守规则可能把有用的新增证据全部挡住。不能在未拆分 no_gain 与 no_safe_replacement、未审查真实 loss 的情况下，断言选择器严格程度不是原因。

最小改法：先建立可证明的 exact evidence identity（conv、完整观察时间、规范化完整正文、时间注释/来源身份），仅以此删除确切重复；未知语义不计为“已覆盖”。将用于新值发现的语义索引与用于删除安全性的支持证明分开。后一阶段若允许替换独有旧事实，应显式使用 query 相关性、被移除证据的答案支持及对照实验验证，不能继续称“全信息零损失”。

## 4. 两臂候选预算与去重

`tools/step4_run.py` 第 3–4 行声称 H 至少 48 下层+16 上层，实际 `MAX_CANDIDATES=40`（第 24 行），`LOWER_SLOTS=48` 从未使用；第 72 行在有 16 个上层候选时只保留 24 个下层候选。上层只取前三 alias、按 folded 字典遇到的顺序取前 16 条、每路由只取首个可用目标，写入 score 后没有排序（第 52–69 行）。下层与上层只在各自通道内去重，没有统一 fact_id 去重。

本次纯离线读取真实 dev80、既有 B 窗口、同一 store/routes，并逐字执行 build_pool 逻辑。下表是全部 80 道开发题的**离线候选重建**，不是已实际执行的 7 次模型响应，也不包含新模型判决：

| 项目 | 结果 |
|---|---:|
| L 总候选槽 | 3,160 |
| H 总候选槽 | 3,160 |
| H 下层槽 | 1,896 |
| H 上层槽 | 1,264 |
| H 跨通道重复槽 | **817** |
| 涉及重复的问题 | **66/80** |
| H 实际唯一候选 | **2,343** |

例如 conv-48#q0033 的 H 40 槽仅 24 个唯一候选；conv-42#q0033 仅 26 个。当前 H 用同样模型调用预算呈现了更少唯一候选，不能据此干净估计高层导航的增量价值。

最小改法：保留同一预注册总候选数；按 fact_id 在合池后去重、合并 provenance，再按声明的 lower 保底与 high 新增配额回填；高层须扫描足够 route 后统一排序，不能按字典顺序抢占；固定相同上下文规则、候选最终完整可见。输出 raw/unique/shared/high-only 数量及实际 token 数。若升级为 48+16，应两臂都使用 64 唯一候选，并给 L 相同额外检索和重排预算。

## 5. 下一轮最低进入条件

1. 修复上述控制，必须真实覆盖满容量接受和满容量拒绝；增加四组原子碰撞反例。
2. 合池唯一候选重复为零；每条接受决定持久化 query、原候选/中心、前后集合、具体 gain/loss、被移除窗、最终证据哈希，不能只落计数。
3. 使用实际观察时间和 W0 注释验证最终证据；中心必须在最终 formatter 后仍然完整可见。
4. 从已收集 6 个 bridge 中逐条审查：模型相关性是否可信、真有新增答案支持、拒绝是 no_gain 还是 no_safe_replacement。此步骤先复用已有模型输出，不新增成本。
5. 完成预定、隐藏历史分数的来源审计后，再决定改候选来源、修选取策略或转 R2。当前审计表的 not_audited 不能支持“摘要没有损失”。

以上为修正测量及执行契约的建议，不是本轮新答题评分或新算法效果结论。
