## 3. 仍需修正的关键问题

### 3.1 两个替换控制没有真正发生替换

离线调用现有控制及选择器可复现：

| 控制 | B 窗口数 | 操作后 | 接受 | 替换 |
|---|---:|---:|---:|---:|
| safe_replacement | 22 | 23 | 1 | **0** |
| no_safe_replacement | 22 | 23 | 1 | **0** |

两个都因为未达到上限 24 而走追加分支。`replaced >= 0` 恒真；“没有替换”也不能证明第二项拒绝了不安全候选。不同事件负例通过的原因是所有窗口被保护，替换循环为空，并未检验关系匹配。

因此“六项控制通过”只能描述原测试返回值，不能称为安全替换与事件判断已经通过验收。

### 3.2 当前 atom 既会漏信息，也会锁住无关信息

`support_atoms.py` 的选择函数没有接收问题。它要求 victim 的**所有**正则原子都被保留，而非只保留该问题所需的支持，任意无关人名或数字也可能让尾部不可替换。

原子值主要来自首字母大写词、年份与数字；key 不含角色绑定、极性、事件身份或观察时间。已经离线复现四类语义不同但 support 集合完全相同的情况：

- Deborah likes running / Deborah likes swimming：小写答案值丢失。
- Jolene recommended Zelda / Jolene never recommended Zelda：否定丢失。
- Jolene 给 Deborah 推荐 / Deborah 给 Jolene 推荐：参与者角色交换丢失。
- 同文字但来自不同观察时间的提及：无法区分，也没有独立事件依据。

不同观察时间不必然是不同事件，但也不能在没有身份依据时自动合并。当前集合相等、gain=0 或 loss=0，均不能作为语义无新增或语义无损的证明。

**建议保留这些 atom 仅作可观察诊断字段，撤出最终选择门槛。** 先用问题条件下的联合重排完成验证，避免继续扩充正则直至难以检验。

### 3.3 上层候选质量与预算比较被重复、顺序污染

按当前代码对全部 80 题离线重建，注意这不是 7 次历史 API 判决统计：

- L 共 3,160 个候选槽位，均唯一。
- H 同为 3,160 个槽位，但只有 **2,343 个唯一候选**；817 个槽位与已有候选重复，涉及 66/80 题。
- H 的实际分配为 1,896 个低层槽位、1,264 个高层槽位。代码中的 `LOWER_SLOTS=48` 未使用；40 槽位配置通常是 24 低层 +16 高层，并非声明的 48+16。
- upper 按折叠字典遍历顺序取前 16 个目标就停止，没有按保存的 score 全量排序，也没有跨通道去重；并不等价于“最相关的 16 个高层候选”。

H 用相同调用预算审核更少的不同候选，因此现在的比较不足以判断高层导航增益。

### 3.4 支持判断、上下文与长期契约仍不完整

- `supported=true` 的提示是“文本支持自身”。它不证明对应正确事件，也不证明比 B 有额外价值；当前筛选器甚至没有收到 B 的支持内容。
- 候选只传中心正文，`context=[]`，未传观察时间。关于指代、推荐回应、相对时间的桥接判断可能缺少必要上下文。
- `render_candidate()` 最后仍执行 `text[:420]`。本次 280 条中心恰好没有被截掉，但这不保证更长中心安全；“centre_first_render_keeps_target=True”在自检里是常量，不能作为测试。
- 返回状态先设 valid，再检查字段，缺失 ID/重复 ID/额外 ID 仍需严格处理。当前 7 次没有缺失，不代表边界已经覆盖。
- step4 没有接入先前约定的路由保护。在 R1 阶段按旧规则回退的题，不应继续花费候选筛选调用；保护谓词是 `not compositional_query()`，不能把所有这类题都叫直接日期题。

### 4.1 填完 20 题来源支持审计

逐题填写 S_source、D_derived、C_L、C_H、B_evidence，引用 source_id、fact_id、观察时间与必要上下文；本轮未答题就把 answer_judge 留 not_run。

标签允许 complete / partial / not_found_after_review / uncertain，说明支持需要直接引用、时间换算、跨句组合还是一般知识归类。`not_found` 必须写搜索范围，不直接等同数据不存在。

原 `lost_in_summary=0` 和 43 道 absent_everywhere 的词面诊断仅作调试特征，不作为本轮决策依据；之前已核对出的四例“原文、派生和 B 都支持”保留为回归。CS:GO 的短词过滤不能删除诊断分母。

### 4.2 填完 40 组候选审核

每组核查来源、问题事件/关系、实际答案值、必要上下文、相对 B 的价值及替换风险。审核时隐藏历史分数与组别；若表里显示 route_levels，先隐藏后判断。

至少分清：

1. 问题相关且 B 缺少必要支持。
2. 问题相关但 B 已完整覆盖，属于重复。
3. 中心需要上下文才能判断。
4. 仅共享人物/主题，属于无关。
5. 引用、角色或时间绑定存在疑点。

原 40 组未必覆盖所有类别，照实报告，不伪造“20 接受+20 拒绝”。额外正负功能控制单独保存，不混入 40 组抽样比例。

交付 `SEMANTIC_AUDIT_COMPLETED.md/json`，汇总实审数和仍未确定项。允许结论 uncertain，但不允许把 not_audited 换名为 unsupported 后算已审。

### 5.3 一次模型调用联合评估，避免粗 atom 再锁死

每臂给同一个选择器：问题、共同 B 前缀和尾部、12 个可选窗口；其中每个窗口有真实 fact_id、完整中心、观察时间及必要上下文。

选择器只可选择已有窗口和事实，输出：

```json
{
  "selected_optional_window_ids": [],
  "removed_base_tail_ids": [],
  "evidence_decisions": [
    {
      "window_id": "existing-id",
      "relevance": "direct|bridge|context|unrelated|uncertain",
      "supporting_fact_ids": ["existing-id"],
      "query_relation": "short description",
      "answer_value_or_needed_link": "supported value or link",
      "constraint_mismatch": false
    }
  ],
  "lost_query_support": [],
  "new_query_support": []
}
```

判断单位是被支持的“主体角色—关系—答案值/必要关系边—事件/状态/时间约束”，不是是否出现某个人名、年份或关系词。

- 允许保留原尾部，不强制新增；有明确相关增量且没有丢失所问必要支持时才替换。
- 无关的别处人物、数字和活动可以不保留，不能要求候选补回 victim 所有正则 atom。
- context 并非默认无价值：若它解释回答所必需的指代或清单关联，可与支持一起选择；必须标明关系和来源，不能当独立答案值。
- 多跳或清单组作为整体核查，多个窗口分别计入预算；不把残缺桥接链塞进剩余槽位。
- 无法确认状态、指代或替换风险时回退 B，不靠自报置信度硬选。

程序验证来源 ID、同对话、保护前缀、总窗口不超过 24、高层新增不超过 4、无重复事实、真实输入可见和 W0 时间格式。**模型负责问题相关性判断，程序不能宣称已经自动证明语义无损；语义质量由已完成审核及独立抽查验证。**

每臂一次批处理调用，使用相同模型、提示、输入/输出 token 上限、重试上限及排序规则；隐藏层级标签和路由推荐理由。完整提示完全相同可共享一次新响应。不要给 H 再加一层额外模型核验而不给 L 相同预算。

初始 token 上限可沿用 24,000 输入、4,096 输出；B 必须完整提供，不能为了塞入候选截断 B。若超限，按共同规则减少完整可选组；B 本身超限则记录 budget_fallback 并返回 B。记录实际成本，不把相同上限称为实际等成本。

### 5.4 修正客户端契约

- 保留现有已验证的鉴权、`trust_env=False`、错误分类和逐题落盘。
- 完整中心不得再 `[:420]`。按 token 管理上下文和候选组，程序对真正发送的中心文本做存在/完整性断言。
- 必须验证 JSON 顶层、ID 唯一性/合法性/完整性、真正布尔值、枚举、引用范围；失败记 invalid_output，不能 valid 后继续当成 unrelated。
- 每条记录保存 question_id、arm、协议哈希、完整可追溯候选和实际文本文件、提示/响应哈希、raw response、实际模型、用量、错误和重试。落盘最终证据字符串与事实 ID，不能只留证据哈希。
- attempted 在发请求前计数；valid、auth/network 等分开，鉴权失败测试不计成功模型判决。自检、探索和正式阶段分别统计。
- 支持断点恢复，同协议复用已落盘请求；改变候选数或提示必须新建协议，不覆盖重试到最佳结果。

## 6. 新控制必须覆盖真实决策路径

修改离线控制，并在新选择器上执行；通过后才允许真实筛选：

| 控制 | 必须发生的行为 |
|---|---|
| 满容量安全替换 | B 恰有 24 个合法窗口，20 保护；至少一个尾部对本题无独有支持。新相关候选使 `replaced == 1`、总数仍为 24，并真实渲染 |
| 满容量不安全替换 | B 为 24，四个可替换尾部都有候选无法补回的必要支持。`accepted == 0`、证据哈希不变 |
| 同人不同事件 | B 留有空位，也必须因为本题关系/事件不符拒绝；不能靠“没有替换位置”通过 |
| 新答案值 | 同一推荐者/接收者、不同游戏名或物品值，可以形成增量；不因人名相同自动 no_gain |
| 角色/否定/状态 | 推荐者受者交换、否定、计划和完成不能被当同一支持 |
| 长中心 | >420 字符且答案支持在尾部；最终真实提示仍完整呈现，不能用常量 True 检查 |
| 跨通道重复 | upper 命中 lower 已有窗口，只占一个槽位，并用后续候选回填 |
| 技术失败 | 无效 JSON、额外或遗漏 ID、超时，记录失败并按协议回退，不算语义拒绝 |

控制中的窗口必须有效、来源可追溯；不要用反复引用同一事实或不存在的中心 ID 拼出一个“满容量”测试。真实例与合成例分开标记。正例功能通过不等于真实题性能有效，二者分别报告。

### 阶段 B：固定的四类均衡小试验

从既有 80 题中每类固定取 5 题，共 20 题，种子 `20261027`；保存 ID 和规则，不按旧正确性或候选接受率选题。按四类交错顺序运行，避免又只看前几道时间题。

- 保护规则命中的题两臂都直接返回 B，不调用筛选器，登记 guard_skip。
- 其余题两臂完成相同预算的联合重排，最多 40 次逻辑筛选；真实调用可因保护及相同提示共享而减少。
- 这 20 题全部按预定协议处理后再总结，不以头几题无接受宣布统计稳定。
- 先报告相关性、替换风险和证据变化；若有新的不同证据需要答题验证，再使用 DeepSeek 统一提示答题/判分。同输入共享；没有证据变化就不重复两臂答题来制造差异。
- 记录真实延迟和用量，不承诺“12 个候选一定 15 秒”。需要并发时从 2 开始并记录限流和失败，不把并发差异混入算法收益。

已有七次调用作为探索记录封存，不与这 20 题新协议合并统计。

| 候选多数无关且已通过独立审核确认，支持存在 D 但到达不了 C_H | 新构建批次做实体/事件/关系目录或检索改造，先比较覆盖。向量检索可作后续预算匹配分支，不与本轮选择器修复同时引入 |
| S 有而 D 缺失/扭曲或无法绑定人物、事件时间 | 进入 R2 保真原文及来源对齐，两臂同底层库，重新比较 Q-H/Q-L |
| B 已有充分支持，主要问题是组合、时间计算或答案表述/判分 | 把统一的答案过程作为独立实验，不再要求高层提供 D 中不存在的新事实 |
| 有效机制与审核完成后，两臂始终同证据或无有用改动 | 封存“当前配置没有形成可测的高层选择收益”；无需继续重复调用或跑两份同输入全量 |

不要把“80 题必须有提升”作为不断调参的要求；若没有值得验证的候选机制，完成负结果和失败分解即可结束本配置。

## 8. 对交接中四个问题的直接回答

1. **是否改结构化或向量检索？** 结构化关系有价值，但先完成审核、排序、去重与问题条件选择器。当前上层不是完整排序结果，尚不能用其低相关率证明需要更换检索范式。审核确认同义关系遗漏后，再做独立索引分支，双方共享公共别名特征。
2. **是否继续 80 题，还是缩到 12？** 不继续旧配置。使用新协议的“12 个可选窗口 +共同 B”，先完整完成均衡 20 题，再决定扩大；不能把部分旧 40 候选和新 12 候选拼成一批。
3. **atom 是否足够？** 不足，而且缺少问题条件。先让它退出最终 gate，用共用模型联合重排与引用检查；不优先投入一套更复杂的正则或专属高层别名词典。若以后做模型抽取，两个对照组共享同一抽取结果并单独核算构建成本。
4. **多少题/接受率可以封存？** 没有通用接受率门槛。低接受可能是 B 已足够，也可能是选择器坏了。功能控制与审核有效、完整执行预定诊断后，可以工程上封存当前配置，无需证明总体“无增益”。若要声称统计学等效或不超过某个实用增益，需要预注册差异界限、功效与配对区间；3.5 题、20 题或一次 80 题零接受都不能提供这种证明。若进入正式比较，按约定两次完整配对及不确定性报告，不挑最高轮次。
