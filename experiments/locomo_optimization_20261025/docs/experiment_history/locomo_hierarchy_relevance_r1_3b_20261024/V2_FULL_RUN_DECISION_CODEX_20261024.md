## 仍不能直接启动的具体原因

### 1. 报告的修复没有接入现行 runner

当前 `r13b_run.py` 仍存在：

```python
protected=json.dumps(payload["protected"], ensure_ascii=False)[:9000]
tail=json.dumps(payload["tail"], ensure_ascii=False)[:6000]
optional=json.dumps(payload["optional"], ensure_ascii=False)[:12000]
```

它仍从 `r13b_prepare` 导入旧 `apply_plan`。旧函数仍按原索引 `pop()`，最后 `[:24]` 截断；正确的 `apply_plan_fixed` 位于另一个修复脚本。测试修复函数通过，不代表当前实际调用路径已修复。

全量报告列出的 `r13b_full_prepare.py`、`r13b_full_run.py`、`r13b_full_answer.py` 在本次核查时也尚不存在，因此这些命令不能被视为已经审核可运行。

### 2. 最新请求与旧状态不能混用

最新候选修复后，18/18 个 planned 请求的签名与现有 `state.done` 不同。但当前 runner 只根据 `qid:arm` 是否存在跳过，不比较输入或协议哈希。

直接重跑会把最新 18 个任务全部按旧状态跳过。旧 19/20 评分也来自 h_seen/BM25 修复之前的证据，不能作为最新 V2 的效果成绩。

### 3. 答题缓存不能仅按证据字符串共享

`r13b_answer.py` 的全局 cache 只按 evidence 匹配。当前 20 题未遇到跨题相同证据，因此没有观察到该问题污染旧评分。

但原冻结 861 题低层请求中，已发现两组不同问题拥有相同证据文本：`conv-26#q0025/q0026`、`conv-47#q0016/q0066`。若全量继续按 evidence 缓存，会把不同问题的答案和判分错误复用。

必须按完整模型输入、角色、模型、温度与端点生成缓存 key；答题和判分分别缓存。同一题三臂确实同提示时共享，跨不同问题不能只因证据相同而共享。

## 启动前一次性验收清单

让 Harness 在正式全量目录一次完成以下事项，通过后直接继续全量：

1. **统一生产入口。** 建立真实 full_prepare/run/answer 脚本；runner 使用完整 JSON 和已测试的按标签交换函数，不再导入旧 pop/slice 路径。不要复制旧代码后假定补丁也已复制。
2. **同路径离线回归。** 经实际 full runner 调用的函数验证：t2/t3/t4 多删除正确；全部已选支持呈现；不裁断 B/JSON；超额、非法 ID、重复和不安全计划显式回退。采用完整 token 预算，不能以字符切片代替。无需为了此项调用模型。
3. **全新协议目录。** 不复用当前 state 或旧筛选响应。冻结数据、索引、规则、提示、实际执行脚本及导入依赖的哈希；实际完整 prompt 的哈希用于落盘和恢复。输入变化则拒绝沿用 done。
4. **可靠恢复和回退。** 技术失败按预注册上限重试，明确失败状态；guard/网络/校验回退均实际写成 B 证据，不留缺文件。每题每臂都有终态，源响应和证据可追溯。
5. **完整提示缓存。** 修复答题/判分 key，添加“两道不同问题、相同证据必须分开”的回归。阶段之间隔离响应，不把旧开发答案缓存当新全量结果。
6. **冻结运行规则后开始。** 可先处理全量中预定的 2–3 道题，检查真实发送文本、交换、落盘、恢复和评分，然后在同一协议下继续全部 861 题。启动自检按正确性通过，不根据这几题得分选版本。

**不再要求最新 20 题先得到正向分差，也不增加 80 题 smoke 门槛。** 本轮最重要的是将“修复存在”变成“实际执行入口确定使用修复”。全量本身用于判断效果，不应预设一定上涨。

## 调用与耗时估算需要更正

407 是可筛选的问题数。L/H 两臂分别筛选时是 **814 个逻辑筛选任务**，不是 407 次调用；若其余 5 道两臂提示完全相同并正确共享，约 809 个唯一筛选请求，重试另计。

按报告的 75 秒/次粗算，串行约 17 小时，而非 8.5 小时。并发和实际 token 会影响墙钟时间，先记录真实速率后更新，不承诺固定时长。

答题和判分也分开核算。如果“900–1,200”指唯一答案请求，判分通常还要另算；不能将它直接当作两个角色合计。B/L/H 最多 2,583 条答案记录及 2,583 条判分记录，实际唯一调用因完整提示共享而减少，按实际日志报告。

主结果应同时列 B/L/H 的四类及总分、L−B、H−L 配对变化、真正高层证据入选数量、失败回退和成本；历史 W0 只作参考。候选不同不等于证据不同，更不等于准确率上涨。
