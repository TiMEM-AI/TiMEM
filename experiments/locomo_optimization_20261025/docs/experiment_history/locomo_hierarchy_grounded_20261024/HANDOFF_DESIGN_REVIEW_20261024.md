# 高层相关性设计审查与下一轮最小实现建议

日期：2026-10-24（Asia/Shanghai）。用途：供主交接规划引用，供 DeepSeek Harness 实现。本文只做设计审查；没有修改已有实现，没有发起模型调用或新评测。

## 1. 判断与边界

当前最需要解决的是：高层找到的线索能否指向“这道问题需要的具体事件或关系”，以及该线索加入证据后是否比被替换的低层证据更有用。继续增加高层摘要长度、提高跨层投票权重或扩大上下文，尚无结果支持。

当前首测净增 5 题、一次独立复测净减 4 题，不能确认高层导航稳定有效。应把下一轮拆成两个问题：

1. 在现有同一 L1/L2 事实库上，改进高层候选选择是否有效？
2. 将原文持久化进 L1 后，同一套高层方法相对新的纯 L1/L2 对照是否仍有增益？

先完成第一个问题，能隔离高层改进；第二个问题可以解决摘要已丢失的原话、指代和细节，但其收益必须单独计算。

不承诺分数必然上升，不用旧全量答案挑选“有利题”，不按题目 ID 或数据集类别决定召回行为。运行时只允许问题文字、所属对话标识、已存记忆和固定配置进入检索。

## 2. 对现有代码的具体审查

审查对象：`grounded.py`、`IMPLEMENTATION.md`、`NEXT_STEPS.md`、`rules.json`。以下分别标识代码行为与待检验推断。

| 位置 / 行为 | 已确认的机制 | 下一轮应检验的调整 |
|---|---|---|
| `construct()` 中 Dice 链接 | 高层每个摘要单元最多链接 2 个子事实；词面相似只产生导航候选 | 将“候选链接”与“支持关系”分开存储；不能把 Dice >= 0.65 改名为语义核验通过 |
| `search(..., 'route')` | 在同源路径折叠前取 top 200 路由行 | 建立去重后的导航索引，再限额；记录折叠前后候选覆盖，检验重复摘要是否挤占候选槽 |
| `scores` 按层级求和 | 同一事实在 L3/L4/L5 各出现一次即可分别贡献权重 | 同源支持只计一份；高层新增的是候选覆盖，不能靠同源摘要层数证明更相关 |
| `protected_dates` | 只检查候选观察时间是否已在前 20 个保护窗口出现；不是事件身份核验，也没有随每次高层添加更新该集合 | 用“新的、被支持的事件 / 关系槽位”判断增量；同一天的另一必要事实可入选，另一日期的无关事实应拒绝 |
| `compositional_query()` | 正则粗判组合问题；`\w+s` 可能匹配 `is` / `does` 等词；直接日期问句全部回退低层 | 移除对形态复数的依赖；先支持显式列表、计数、比较、关系连接；未知意图回退。第一阶段保留直接日期题保护，待原文事件 / 时间绑定完成再做日期路由消融 |
| `window()` | 命中附近各两条，必要时再加会话开头两条 | 后续改成“最小支持窗口”；开放窗口与支持事实分开标记，避免开场话题反复进入不同候选 |
| `render()` | 事实日期取下层；时间注释有原文字符区间，但下层整条摘要未逐条证明来自同一事件 | 保留这一日期来源规则；不要把“相同观察日期 + 相同短时间词”当作事件语义对齐的充分证据 |

补充结构统计由主任务直接检查 `hierarchy_plan.json` 和 `store.json` 得到：L3 的 272 个节点均只有一个 L2 子节点；L4 的 207 个节点中 149 个只有一个子节点；L5 的 86 个节点中 18 个只有一个子节点。6,731 个有导航链接的底层事实中，4,695 个同时具有 L3/L4/L5 链接，1,502 个具有两层链接，534 个具有一层链接。

这些统计支持“先检查结构退化与同源重复”的优先级；不能据此断言跨层 RRF 已被证明导致分数下降。单子节点也不一定完全无用：若它形成了有来源的别名或检索措辞，仍可作为同一支持单元的检索入口，不能获得额外投票。

## 3. 保留时间层级，明确每层工作

保持现有 L3=日、L4=月内周、L5=月的树定义。以下是每一层增加的索引职责，不是另造三个不同时间体系，也不向高层添加未经原文支持的新事实。

| 层级 | 可提供的检索信息 | 不应直接作为作答事实的内容 |
|---|---|---|
| L3（日） | 当日人物与事件目录、代词与会话实体线索、事件中各陈述的顺序；单 L2 子节点时优先复用其支持集合 | 从同一日推导“同一事件”；把会话观察日当事件发生日 |
| L4（月内周） | 跨日的同一事件延续、计划→完成 / 取消等有明确来源的状态边、同一关系的多条证据；跨周只通过明确引用边连接 | 因处于同周就合并活动；把计划、完成、回顾揉成一个无状态摘要 |
| L5（月） | 主题 / 实体 / 关系的月度入口，以及指向具体周、日和叶子证据的目录；可为枚举问题提供跨周覆盖 | 用“通常喜欢 / 一贯如此”等概括代替具体事实；从月窗口生成精确日期 |

L3/L4/L5 的总结仍可用于召回候选，但最终证据应该回到同一份底层事实或原文。高层的有效贡献应表现为：找到了低层直接检索遗漏的、与问题有关的底层证据，或者组织出有来源的必要关系链。

## 4. 数据契约：事件身份、来源、状态与时间分开

建议新增独立的 `navigation_v3.json` / SQLite 表，不覆盖当前冻结快照。最小字段如下：

```json
{
  "navigation_id": "stable-content-id",
  "conv_id": "conversation-id",
  "node_ids": ["L3/...", "L4/..."],
  "levels": ["L3", "L4"],
  "support_family_id": "hash-of-canonical-leaf-support-set",
  "candidate_fact_ids": ["fact:..."],
  "supported_fact_ids": [],
  "candidate_status": "lexical_candidate",
  "event_id": null,
  "event_identity_status": "unresolved",
  "participants": [],
  "predicate": null,
  "object_or_topic": null,
  "state": "unknown",
  "polarity": "unknown",
  "observed_at": null,
  "event_time": {
    "raw_phrase": null,
    "grain": "unknown",
    "normalized_value": null,
    "approximate": null,
    "anchor_quote_id": null
  },
  "support_spans": [],
  "relation_edges": [],
  "aliases": [],
  "construction_method": "deterministic-v3"
}
```

约束：

- `event_id` 是来源确定的事件身份，不是关键词聚类标签。找不到明确同一事件依据时允许多个候选事件，不能强行合并。可另设 `topic_cluster_id`，不得与 `event_id` 混用。
- 主体、活动、对象、关联人物应保留来源及未知状态。同一人物参加两次同类活动通常是两个事件；同一活动从邀请、计划到完成可以是同一事件的多个状态陈述，必须存在可核验的连接依据。
- `planned / ongoing / completed / cancelled / hypothetical / unknown` 与 `affirmed / negated / unknown` 分开。保留每条陈述的状态，不用“最后一条必然正确”覆盖历史。
- `observed_at` 表示说话 / 观察时间；`event_time` 是原话谈及的事件时间。允许事件时间未知、范围或模糊，不从父节点周/月范围补出某一天。
- 每个确定的字段都附来源；同义词表只做检索扩展，不能把普通近义关系当事件一致性的证明。
- 候选链接、来源有效性、问题相关性、证据增量是四个不同状态；不要只有一个含混的 `verified=true`。

原文阶段再增加 `quotes` 表，保存 `quote_id/source_id/conv_id/observed_at/role/original_text/position/prev_id/next_id`。旧摘要另存 `abstract`。原文字符串及其时间粒度在构建时持久化；运行时只读新 L1 数据库。

## 5. 两步筛选：候选生成不等于支持核验

推荐流程：

```text
问题文字 + 对话 ID
  -> 直接叶子检索
  -> 同源折叠后的 L3/L4/L5 导航检索
  -> 展开到叶子候选 / 明确关系包
  -> 统一候选池去重
  -> 来源与事件状态检查
  -> 同一问题相关性重排
  -> 证据增量检查 + 同预算选择
  -> 原有 W0 证据格式 + 原有答题流程
```

### 5.1 候选生成

对导航条目先按实际支持集合和规范化文本折叠。相同子事实集合可以保留多种有来源的检索措辞，但命中同一支持家族只产生一个候选贡献。单子链且支持集合相同的 L3→L4→L5 不重复展开。

不得为了增加“独立支持数”把同一原话的改写拆成多个家族。多个独立原文提及可保留多个来源，但“来源更多”也不自动等于“更能回答这道问题”。

候选阶段允许较宽松的词面命中；高层文本和事件字段的作用是发现候选。事件字段未确认时仍可作为低置信索引线索，但不能推动证据通过后续支持门槛。

### 5.2 来源有效性检查

确定性检查：同一对话、实际后代、引用 ID 存在、字符区间完全匹配、原文版本 hash 一致、观察时间与叶子来源一致。检查失败立即拒绝，不用其他日期或父层概括修补。

这一检查证明“候选确实有该引文 / 子事实”，不证明“引文支持高层整条概括”，也不证明“引文回答了问题”。

### 5.3 问题相关性检查

至少检查主体、所问活动 / 关系、对象或相关人物，以及问题是否要求已经发生、计划或偏好。只有人名相同、主题相近或日期新，不够通过。

对单事件问题，候选必须指向该事件或明确的上下文解释；对列表 / 计数问题，候选可属于多个事件，但每项必须满足同一个可枚举条件；对多跳问题，允许多个不同事件通过被支持的关系边连接，不能要求所有节点都属于同一个 `event_id`。

“电影或公园邀请”与“后来去吃冰淇淋”即便涉及同一个人，也不能仅因活动词或邀请主题接近而互相替代。这类例子可作为设计说明；不能把现有题的字符串做成特别分支。

无模型版只能实施明确的实体、活动词、状态和来源约束，应该标注 `symbolic_relevance_check`，不能声称它已完成通用语义蕴含验证。无法可靠判断的高层增补应回退。规则可保守，覆盖率下降必须报告。

### 5.4 证据增量检查

新增内容应补充以下至少一项：所问关系的另一个必要端点；同一事件的必要状态或时间陈述；满足枚举条件的另一条独立事项；解决当前指代歧义的上下文。

“另一观察日期”不再是一项增量理由。还要检查被替换窗口：如果新内容不能在固定相关性评分上优于将被移除的低层窗口，保留低层结果。候选包必须作为整体计入预算；多跳链不能只留下容易命中的一个端点。

拒绝原因应为结构化枚举，例如 `no_subject_support`、`event_ambiguous`、`state_mismatch`、`only_topic_overlap`、`duplicate_support`、`no_new_slot`、`budget_exceeded`、`source_invalid`。每次拒绝都回退已有低层候选，不输出空白补位或自造摘要。

## 6. 推荐最小实现：先做无需新模型的 V3-A

第一阶段保留当前 7,157 个事实与原 W0 渲染，新增以下组件即可：

1. `build_navigation_v3.py`：折叠同源支持路径；保留层级与原路由 ID 便于审计；构建折叠后的 FTS 索引；统计候选槽位重复率。
2. `retrieve_v3.py`：汇集直接叶子与高层候选；最终统一以叶子内容和问题重排；高层层数不进入最终相关性评分。使用确定性主体 / 关系 / 状态约束；去掉“新日期必优”和形态复数分类。
3. `select_evidence_v3.py`：保留前 20 个低层窗口；最多改变后 4 个；对新增及被替换内容记录评分、支持、缺失槽位与拒绝原因。第一阶段继续使直接日期查询完全回退低层；这项保护意味着不能期待该部分问题出现高层收益。
4. `audit_v3.py`：来源、去重、跨对话、时间、预算、同源折叠和冻结输入检查。

可采用配置化的固定权重评分，但应只用新的开发会话选择权重；不能拿全量正确性训练“何时调用高层”。未知状态不应被默认为满足条件。最小版没有可靠语义解析能力时，以保守拒绝换取可解释性，再决定是否需要模型版本。

### 6.1 候选预算与证据预算

建议将两个实验组共同定义为最多 600 个去重后的叶子候选：纯低层组取前 600 个直接候选；高层组先取前 400 个直接候选，再加入最多 200 个高层发现的叶子候选，不足时用后续直接候选补齐。高层单位展开出的多个叶子都占这个限额，不得把一个大型摘要当成一个免费候选。

两组使用同一重排器、同一上下文形成逻辑、同一最多 24 窗口上限、同一 token 上限以及同一 8,000 字符新增时间注释上限。直接命中不足时不捏造候选来填满上限；实际候选数、证据 token 和检索耗时单独报告。

这是候选评估数量的控制，不能宣称索引结构不同就能保证完全相同 CPU 耗时；应同时报告索引访问次数、延迟、读取行数和候选数量。可以增加“纯低层更大检索预算”敏感性对照，检验提升是否仅来自更多候选。

“前 20 个保护窗口”在两组中应由同一直接检索过程形成。新增原文阶段如改变窗口长度或构造，应同时更新两个实验组，并重新建立对照。

## 7. 有模型时的 V3-B：只在 V3-A 诊断说明需要时引入

若主要遗漏来自同义活动、复杂指代或跨句状态，可增加统一的候选支持重排器。不要只给五层组增加一次更强的回答模型调用。

建议先用每题最多 80 个候选、每批 20 个、最多 4 次固定上限调用的配置；这些数字是待开发阶段确认的初始预算，冻结后不随题目正确性改变。纯低层组也使用相同重排 / 验证模型、提示模板、温度、最大输出 token 和调用上限。

重排器输入只含问题及候选叶子 / 原文窗口。高层来源、层级数和高层生成的“推荐理由”不输入核验器，以免它把导航说法当事实。返回字段限定为候选 ID、可逐字匹配的支持引文区间、涉及主体 / 关系 / 状态、是否相关及拒绝原因；不要求它输出参考答案。

输出 ID、引文或 JSON 无效则拒绝该结果并回退；设置两组相同的固定重试上限。支持核验本身也是模型判断，不能把它的置信度当作正确性的证明。至少在开发集做盲审或构造负例审查：同人物不同事件、计划与完成、否定与肯定、相同主题不同对象、同源改写重复。

构建期若使用模型提取事件字段，应分别记录构建调用与查询调用；原文恢复后的两个实验组共享同一事件 / 实体解析和叶子索引，五层组仅额外拥有父层导航与关系组织。应披露高层构建的额外计算成本。

## 8. 原文 L1 阶段：独立构建，重新建立对照

只有确认当前遗漏与摘要缺失相关后，再实施原文持久化；这一步也可以作为独立研究分支，但不能混入 V3-A 的高层贡献。

原文从冻结数据在构建期写入 L1；保留说话人、原始内容、会话内顺序、原始时间短语，提供来源字符区间。摘要仍保留导航价值，但原文引用与摘要必须显式区分。不能用模型生成文字填补不存在的原文。

原文窗口应从支持句向两侧最小扩展以恢复指代或问答关系，扩展上限在两组完全一致。不以“同一天”直接拼成大段背景。时间注释绑定实际引用的短语与事件支持，不把同一会话另一事件的 `last week` 注释转贴过来。

原文事件和时间短语唯一绑定后，才增加“开放日期路由”独立消融。仅对明确事件主体、活动、状态和来源时间锚点的候选开放；歧义或计划 / 完成冲突保留低层回退。这个消融可回答高层是否能帮助时间题，不能和引文恢复同时改完后合算一笔收益。

必须比较：

| 组别 | 底层内容 | 检索导航 | 回答的问题 |
|---|---|---|---|
| S0 | 现有摘要事实 | 改进后的纯 L1/L2 | 当前底层对照 |
| S1 | 与 S0 完全相同 | V3 高层导航 | S1−S0：现有事实库上的高层贡献 |
| Q0 | 持久化原文 + 摘要 | 同预算纯 L1/L2 | Q0−S0：原文恢复及其统一索引的贡献 |
| Q1 | 与 Q0 完全相同 | 同一 V3 高层导航 | Q1−Q0：恢复原文后的高层贡献 |

S1−S0 与 Q1−Q0 是两次独立的高层配对比较。Q1 与旧 W0 的差值只能用于历史对照，不能直接归因为高层。

## 9. 消融、冻结与复测顺序

推荐按以下顺序推进，不在一个版本里同时叠加全部改造后才解释原因：

1. 来源与结构审计：同源折叠、支持家族、失败事件映射、重复候选、状态冲突。此阶段不调用答题 / 评测模型。
2. 新开发会话 smoke：当前纯低层；同预算的改进纯低层；只加路径折叠的高层；再加事件与增量门槛的高层。开发分数只能用于选版本，不能作为正式验证分数。
3. 如果语义匹配确有必要，增加 V3-B 与其预算匹配的纯低层对照；不要同时在此阶段恢复原文。
4. 冻结一个最小候选版本与对照。封存存储、代码、规则、模型、提示、问题列表、开发范围、采样方式、全部哈希以及复测次数。
5. 运行旧 861 题全量配对比较作为回归 / 历史结果；明确其已被多轮查看，不能称未见测试集。有新增会话时另做按会话隔离的验证，并禁止根据其分数回调参数。
6. 预先固定独立复测次数；建议两次完整运行，预算不足时复测所有“冻结后证据输入不同”的题。选择依据只能是输入 hash，不得依据首测正确 / 错误或类别表现。只复测子集时报告子集结果及配对效应，不能拼接出一个假定的第二次完整准确率。
7. 若下一步恢复原文，重走 Q0/Q1 的对照、冻结及复测流程。

独立轮次使用独立模型响应缓存；同一轮两组的完全相同模型输入可以共享响应。对输入变化导致的配对差异、答题随机性和评测随机性分别保留信息。不能把多次对同一批问题的调用当成新的独立样本增加显著性。

旧 40 题是已用开发样本；旧 861 题也都已被多轮评测。若没有新对话，报告只能说“现有 benchmark 回归结果”，不能通过重新划分题目制造新的未见集。

## 10. 必须交付的诊断与验收

每题记录：直接候选、高层候选、折叠家族、最终支持来源、状态 / 时间检查、候选接受 / 拒绝原因、被替换证据、实际输入 hash、窗口与 token 用量、模型调用数 / 响应 ID。原始题目类别和 gold 只允许进入离线评测与汇总模块。

除四类分数、总分、配对修复 / 退步、McNemar 检验外，至少报告：

- 高层候选中，多少只共享人物 / 主题而被拒绝；多少能提供新的必要事实。
- 折叠前后 top-k 的独立支持家族数、候选覆盖差异和原文 / 事实重复率。
- 正确证据已存在但加入高层后退步的数量及样例；这类回归说明问题在干扰或排序，不能归因于未召回。
- 所问事件与被召回事件错配、计划 / 完成错配、否定丢失、观察时间 / 事件时间混用的审查数量。
- 无法找到原文支持的比例、回退比例、证据完全不变比例和额外计算成本。

硬性正确性要求：跨对话泄漏为 0；无效引文为 0；用父层时间覆盖子事实时间为 0；直接用 gold/category/qid 或旧判分参与召回为 0；高层推断未经支持进入答案证据为 0。

研究成功条件应在测试前写明，而非见分数后修改。建议要求全量配对收益在预定复测中方向一致，并单独检查四类任务；若没有预注册非劣界，不能宣称“其他类分数保持”。样本较少的多跳与推理类别需要给出题数和不确定性，单次持平不等于已证明无退化。小幅提升且检验不确定时，结论写“候选方案，尚待新会话验证”。

最重要的交付结论应是：哪一项改造增加了相关证据，哪一项减少了干扰，是否在新的同预算纯低层对照上得到可复现增益。五层是否都出现在答案上下文中，不作为成功指标。
