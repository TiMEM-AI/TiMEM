# L3–L5 相关性优化：改动记录、实验结果与 DeepSeek Harness 执行规划

日期：2026-10-24（北京时间）  
状态：**交接规划，下一轮方案尚未实现、尚未测试。** 本文中的现有分数来自已完成实验；建议参数和验收标准属于下一轮预案。本文编写期间只做文件、结构和案例审计，没有重新答题或重判分。

## 1. 建议采用的方向

高层确实可以帮助找到低层漏召回的证据，但当前结果还不能证明 L1–L5 稳定优于 L1/L2。下一步的目标应是：**让高层定位问题所需的事件和关系，再选择有来源支持的证据组；高层重复出现、主题相似或日期更新本身，不应提高入选优先级。**

建议分两阶段，依次实施：

1. **R1：先优化高层相关性，保留现有 7,157 个低层事实。** 折叠同源导航路径，区分问题相关性与来源支持，按完整证据组重排，检查增补价值及替换损失。用相同语义处理预算的 L1/L2 对照，直接检验高层的贡献。
2. **R2：在独立批次中补充保真 L1 原文及实体、事件对齐。** 两个对照组一起获得同一份原文库，然后再测高层增益。有原文事件与时间的可靠绑定后，才单独放开直接日期题的高层导航。

这样可以分别回答“现有事实是否选得更准”和“摘要是否已经丢失必要信息”。不要把 R2 恢复原文的提升记在 L3–L5 名下。不要以五层每题都出现在最终上下文中作为目标；允许候选增补被全部拒绝，并逐字回退到预先保存的共同低层结果 B（定义见第 6.5 节）。

**优先级：R1 的候选去重、语义证据组筛选与受控全量优先；R2 是独立的下一阶段。不要同时重写五层摘要、改答题提示和换判分模型。**

## 5. 本次深入审计发现了什么

### 5.1 高层重复结构需要折叠，但保留检索别名

本次从 `hierarchy_plan.json` 与 `store.json` 重新统计：

| 层级 | 节点数 | 仅有一个子节点 |
|---|---:|---:|
| L2 | 272 | 149 |
| L3 | 272 | 272 |
| L4 | 207 | 149 |
| L5 | 86 | 18 |

6,731 个低层事实有至少一个高层链接，其中 4,695 个同时被 L3、L4、L5 链接。这个 6,731 是“任何合格链接”数量；此前 6,726 是“强词面链接”数量，门槛不同，不应混用。

当前融合在每层内部去重，但仍累加同一事实来自不同层的分数；原始高层 top-200 也在同源折叠前截取。因此有两个待检验的机制：重复摘要挤占候选名额；同源事实得到重复的层级投票。结构统计证明重复存在，尚未证明它造成多少错答。

实施时保留原树和层级来源，将相同证据目标的多条路径折叠为一个候选组。单子节点且无新增事件关系的父节点作为导航别名，不增加“独立支持次数”。有用的新称谓、事件标签仍可参与检索，不能直接删除所有高层文本。

### 5.2 来源支持、问题相关性、增补价值是三个不同判断

一条记忆可以是真的、有合法来源，也和题目共享人物，却属于另一次活动。当前高层与子事实的相似度主要回答“可能链接到哪条事实”，没有回答“该证据是否符合题目所问的参与者、动作、对象和条件”。

候选进入答题上下文前要分别通过：

1. **来源支持**：候选描述能否由持久化事实/原文支持；每个引用 ID 和区间有效。
2. **问题相关性**：整个证据组是否覆盖问题中的关系、约束或一个必要的推理跳步。
3. **边际价值**：在已选证据之外补充了什么；是否挤掉更有用的低层证据。

“新增观察日期”只作为覆盖统计，不再作为奖励或硬门槛。同一天可能有互补事实，不同天也可能只有无关信息。

## 6. 推荐的数据与检索设计

### 6.1 保留时间层级，为各层增加明确的检索职责

不改变现有 L3=日、L4=月内周、L5=月的定义。以下是建立在原时间树上的检索视图，不是新声称的 TiMEM 原生机制。

| 层 | 建议索引内容 | 允许贡献 | 需要避免 |
|---|---|---|---|
| L1/L2 | 事实/引文、参与者与角色、动作关系、对象、状态、来源时间 | 提供两臂共同可用的事实、实体与事件信息 | 仅高层获得更完整实体信息，导致不公平对照 |
| L3 | 当日事件目录、角色称谓、同一事件的证据组 | 找到相关片段，补全请求/回应、指代或清单 | 单子节点重复摘要增加独立权重 |
| L4 | 周内不同事件的关系索引、状态转移和事件成员 ID | 找到有来源支持的桥接事实或其他所需事件 | 把同人物、同主题、相邻时间自动当作同一事件 |
| L5 | 月内主题/实体到事件集合的目录，已知状态变化的索引 | 缩小候选范围、定位跨周事实；跨月问题可检索多个 L5 节点 | 把月度概括、画像推断直接当作具体事件证据 |

所有“关系”和“状态转移”都要有底层来源 ID。只知道 A 与 B 同时出现时，只能保存共现，不能生成因果、完成或身份关系。

### 6.2 统一的事件提及与证据组

建议新建独立的结构化索引。R1 的底层仍为派生事实；R2 的底层切换为持久化原文引文。两阶段分别标记 `support_basis=derived_fact` 和 `support_basis=original_quote`，不能混称原文验证。

建议最少字段：

| 对象 | 字段与规则 |
|---|---|
| 事件提及 | `mention_id, conv_id, subject_refs, predicate, object_refs, participant_roles, modality, polarity, source_refs, observed_at` |
| 事件时间 | `raw_phrase, grain, normalized_value/anchored_value, source_span, resolution_status`；观察时间另存 |
| 证据组 | `bundle_id, mention_ids, source_ids, context_ids, relation_edges, provenance_levels` |
| 事件聚合 | `event_cluster_id, member_mention_ids, link_basis, status`；与具体提及 ID 分开 |
| 高层路由 | `route_id, parent_node_ids, target_bundle_ids, search_aliases, scope, support_status` |

字段规则：

- 稳定 ID 由对话、来源 ID、提及区间或规范化目标集合生成；不包含问题 ID、答案或正确性。
- `modality` 区分计划、愿望、邀请、实际发生、习惯、未知；`polarity` 区分肯定、否定、未知。字段只表达材料已有信息。
- 实体映射在对话/说话人作用域内建立。有原文或可信元数据才确定别名；不把所有 User 全局替换成某个人名。无法解析则保留未知，不能猜测。
- 单条句子可含多个事件；同一事件也可有多次提及。不要把 `观察日期+人物+活动词` 当作事件唯一键。
- 只有明确同一对象、情境或指代链时才合并事件；不确定关系保留候选边。计数去重要按事件身份，不能只按文本近似或观察日期。
- 支持一条路由的多个层级不是多份独立来源。证据覆盖按唯一事实/引文、事件和问题槽位统计。

### 6.3 同源路径折叠与候选融合

1. 构建索引时，为相同目标证据组生成一个规范路由对象，将多层路径放入元数据；检索别名去重后保存。
2. 同一目标的完全重复别名不重复贡献词频。保留不同但有来源的表述，特别是实体别名与关系词。
3. 候选截断以规范路由组为单位，避免在原始重复 top-200 截断后才发现大量重复。若临时采用扩大取回再去重，必须记录真实扫描量和去重后覆盖，不宣称与构建时折叠等价。
4. 同一证据组的多层分数取最佳或一次统一重排分数，不按出现层数累加。L3/L4/L5 只保留来源路径标签。
5. 事件组合包含多个独立事实时，组合关系须有支持；不能仅因共享一个叶子就错误折叠不同推理路径。

### 6.4 查询解析与语义筛选

运行时接口只接受 `query_text` 和 `conv_scope`。问题 ID 仅由外围评测器用于落盘；`category`、`gold`、历史答案和判分不能传给路由器、解析器、重排器。

共享查询计划：`entities, target_relation, requested_slots, temporal_constraints, modality, list/count/comparison flags, unresolved_fields`。可以用确定性解析或一次模型解析；两臂共享同一结果和版本。输出不包含猜测答案。

语义筛选读取的是候选证据组，并输出可核验的短字段，而不是一段用于答题的新摘要。输入显式剔除 `provenance_levels`、路由分数、重复层数和高层生成的推荐理由，只保留问题、底层事实/引文及两臂共同拥有的事件关系字段。候选用与层级无关的 ID；来源路径留在程序审计中：

```json
{
  "bundle_id": "existing-id",
  "support_status": "supported|partial|unsupported|unknown",
  "relevance": "direct|bridge|context|unrelated|unknown",
  "covered_slots": ["existing-query-slot-id"],
  "supporting_source_ids": ["existing-source-id"],
  "supporting_spans": [],
  "new_event_or_relation_ids": [],
  "conflicting_constraints": [],
  "context_needed_ids": []
}
```

`partial` 必须能裁剪到已支持的子组，再重新检查；不能把未支持的部分一起加入。输出 ID、区间、角色枚举都由程序校验；未知或无效输出回退。模型自报置信度不能代替来源检查，也不当作校准概率。

多跳题允许 `bridge`：它不必直接回答终点，但必须从题目中的实体/事件锚点，通过有来源的关系，连到另一个必要槽位。只共享主题不算桥接；初版最多扩展两条关系边，并记录每条边的来源。不要要求每条桥接句都包含完整问题词，否则会损伤多跳召回。

新增或替换候选的上下文按“解释指代、问答配对、补全同一清单或关系”保留。初版可以继续生成 ±2 候选，但只输出通过组级支持的上下文；来源不足时可保留明确标记为上下文的原句，不能据此捏造实体或事件。新增候选不再无条件复制会话开头两条；R1 受保护的共同低层窗口仍逐字保留原格式，R2 如改变公共窗口规则则同时更新两臂。

### 6.5 增补、替换与回退

先独立生成一次确定性的共同低层结果 **B**：同一直接检索、最多 24 个旧式窗口、前 20 个作为保护前缀；存储窗口列表及最终证据文本哈希。B 不依赖任一臂的候选批处理结果。两臂共用 B、查询解析结果及相同的增补选择器。

L 与 H 分别在相同预算下，从各自候选池选择至多 4 个尾部窗口。下面的来源、问题相关性、边际价值和替换检查适用于两臂所有备选；H 的高层候选只有在这些条件成立时才改变最终证据：

- 有合法的底层支持，且符合题目明确给出的参与者角色、关系、状态及时间约束。
- 整个证据组增加一个未覆盖的所问槽位、列表成员、事件或必要关系边；单纯重复、补充闲聊或多一个日期不合格。
- 与拟替换的低层尾部窗口比较后，不丢失其独有的必要支持。未知是否可替换时保留低层窗口。
- 处于同一证据窗口数和 token 上限；不通过给高层更多最终上下文获得优势。

记录 `added_source_ids`、`removed_source_ids`、`covered_slots_before/after`、`rejection_reason` 和实际渲染顺序。某臂全部备选增补被拒绝或解析失败时，直接返回已经保存的 B，要求证据文本哈希一致，不能再次重新评分或拼装 B。

**B 与经过重排后的 L 最终结果不是同一个概念。** H 无高层入选时，仍可能因候选池中低层尾部的选择不同而与 L 不同；此时须单列“最终无高层来源但两臂证据不同”的题数及原因，不能宣称全部退回 L 或把这种差异算作新增高层证据命中。若在语义筛选前 H 就没有合格高层候选，使用与 L 完全相同的候选池和输入，复用共同筛选结果。若未来要求 H 在任何高层拒绝情况下都逐字等于 L 的最终结果，需要额外共享完整 L 选择阶段，并为 L 配置对称的增补计算，另行冻结该协议；不要暗中给 H 增加一次筛选调用。

冲突事实不能简单删除：若题目询问变化、计划与完成的差异，需保留有时间及来源的不同状态。若只是候选与题目明确事件冲突，则拒绝其作为该事件的答案支持。未知状态保持未知。

## 7. R1：优先执行的最小改造与实验

### 7.1 范围

在 R1 中，“supported”最多表示被现有派生事实支持。构建时不引入原始全文，不把摘要核验升级为原文核验。若发现正确事件已经在 L1/L2 摘要中丢失，记为信息缺口，转交 R2，不能临时读取外部 L0 填答案。

### 7.3 对照组与共同计算预算

| 组别 | 候选来源 | 作用 |
|---|---|---|
| `L`：公平低层对照 | 同一 L1/L2 事实库、共享实体/事件字段、直接检索候选 | 接受与 H 同样的查询解析、语义筛选和证据预算 |
| `H`：高层相关性方案 | 与 L 相同的低层基础，另经折叠后的 L3–L5 导航补候选 | 唯一主要差异是高层组织方式能找到哪些候选 |
| `H_fold`：开发消融 | 仅折叠路由、保留现有筛选逻辑 | 定位去重/层级投票变化；初版只在开发集运行 |

主结论使用新鲜运行的 H−L，不能用 H 与历史 718/861 直接相减代替受控比较。若只给 H 额外模型重排，其成绩只能称为“增加计算的整体系统”，不能作为层级效应。

以下是建议的初始工程上限，**尚未经测试，不代表最优参数**；只允许在开发阶段调整，冻结后不得改变：

- 低层检索返回上限保持 400；高层以 200 个规范路由组为返回上限，另记原始路径数。高层返回及展开会带来额外索引工作，报告读取量、构建成本与耗时；这不是总检索 CPU 严格等成本的实验。
- 最多 **64 个原子窗口槽位**进入共同语义筛选，包含 B 的全部至多 24 窗口（其中前 20 个受保护）。L 全部来自低层；H 保留至少 48 个低层槽位，另至多 16 个由高层定位，不足则用低层补齐。先放入 B，再按冻结排序填充；实际候选不足时不造条目补齐。
- R1 每个原子窗口最多 7 条现有事实，且不跨观察时间，事实正文不改写。证据组可由至多 3 个原子窗口组成；每个窗口分别占候选槽位和最终 24 窗口预算。两跳链需要 3 个窗口就占 3 个，不能作为一个免费的大组。成员共享时按唯一窗口/事实去重；组不能完整装入剩余预算时不输出残缺关系链。
- 高层路由仅定位窗口和关系，不直接传递整份摘要。最多 16 个高层窗口在调用语义筛选前就限额；不能把 200 个大组全部交给模型后才声称只用了 16 个。
- 两臂固定保护相同的前 20 个低层窗口，最终最多 24 窗口。H 的高层替换仍至多 4 个；替换需满足第 6.5 节条件。
- 若采用模型筛选：两臂相同模型、提示、一次批处理调用上限、24,000 输入 token 上限与 4,096 输出 token 上限；使用同一确定性截断策略。实际有效候选数和 token 必须统计，不能把相同上限称为实际成本完全相同。
- 查询解析每个问题至多一次，两臂共用。跨来源名称规范化属于公共特征，不仅提供给 H。
- 最终答案、判分模型与提示和温度沿用现有设置；主证据仍用 W0 格式化器，新时间注释仍限 8,000 字符。

当候选超过共同 token 上限时，先保证 B 完整保留，再从可选候选尾部按统一规则删除完整组；不能为塞入高层删 B。若 B 本身超出筛选器预算，记为预算回退并直接用 B 答题，不静默截断 B。64 槽位输出若经常被截断，开发阶段改用同样的分批预算或更紧凑格式并重新冻结；不得在全量中对 H 单独追加调用。调用/解析失败允许同样的技术重试，超过预注册重试次数则一致回退并记录，不挑答案重试。

以上控制的是主要语义评估和最终作答预算。若希望进一步区分“高层组织”与“额外候选查找成本”，在开发阶段增加一个只扩大低层检索返回量的敏感性组，公开其实际读取与用量；不能仅凭相同 64 槽位声称总成本完全相同。配套设计审查中的 600 叶子/80 候选是备选建议；**本主文档的 400 返回、64 原子窗口槽位和调用上限是本轮初始执行口径**，不得混用两份参数。

### 7.4 执行顺序与停止条件

1. **核验输入。** 检查旧文件哈希、节点数、事实数和 861 题集合；用旧请求/结果重算本文分数，无需重新调用模型。
2. **建立共享索引及高层路由。** 构建模块不访问题库；结构化字段只来自输入记忆。保留未解析/无支持状态和所有排除计数。
3. **先做不依赖答题分数的审计。** 检查跨对话边、无效 ID、未知引用、日期覆盖、同源折叠、组级上下文及逐字回退；硬性不变量必须全部通过。
4. **冻结开发样本。** 优先使用项目中未使用的新会话作开发。若没有新数据，固定一个至多 80 题开发 smoke，目标每类 20 题，种子 `20261025`，排除原 40 题和本文已检查的案例；可另把这些案例列为回归集。某类排除后不足 20 题时取全部剩余题并公布实际分母，不放回被排除的题凑数。它们仍来自已多轮评测的旧数据，明确标注为开发用途。保存实际 ID 和选样规则，不能按结果换题。
5. **开发与机制消融。** 在同一开发集比较 L、H_fold、H，另外人工抽查至少 40 个被接受或拒绝的高层证据组，覆盖直接支持、桥接、上下文、同日互补和事件冲突。H_fold 分数只用于机制定位，不升级为新的正式主比较。所有开发版本保留。
6. **冻结正式协议。** 固定最终规则、模型提示、全部源数据哈希、代码版本、评测问题集合、复测次数和报告字段。smoke 主要验证请求完整性与机制；不能因一两题得分略高就认定有效。
7. **准备两臂 861 题证据。** 查询解析和语义筛选结果一并落盘，记录检索层、引用、增删事实与原因；准备阶段不读取 gold。完成后冻结证据哈希。
8. **完成两次全量配对。** 每次均对两臂各 861 题重新答题及判分，共两次；证据保持固定，答题/评分响应缓存按重复批次独立。组别按预设种子交错或平衡执行，减少调用时段差异。第二次不改规则、不换题，不因第一次成绩选择是否运行。
9. **只报告，不追着正式错题改规则。** 输出两次完整分数和配对比较。若效果反向、来源审计不通过或单跳持续退步，保留失败结论和冻结产物，进入 R2 或新的研究批次，不能在相同正式目录继续试到变好。

两次正式全量共有最多 6,888 条“答题/判分逻辑记录”（861×2 臂×2 次×2 角色），相同请求共享会减少实际调用；查询解析、语义筛选和构建费用另列。固定证据复测衡量的是答题/判分波动，不覆盖语义索引生成和重排的随机波动；若要声明端到端稳定，还需另行预注册重建/重新重排验证。

## 8. R2：保真 L1 与更精确的时间导航

R1 结束后，再根据失败分解决定 R2 的重点。进入 R2 的依据包括：必要细节在现有低层事实库缺失、人物/指代无法由摘要确定、事件与时间短语无法唯一绑定。不能仅因为一次全量分数不够高就把多种改动混在一起。

### 8.1 将原始引文持久化到新 L1

构建阶段读取冻结 `aml_sources.sqlite` 的 5,882 条消息，写入新批次 L1 引文表：

`quote_id, source_id, conv_id, session_id, observed_at, role, speaker_ref, seq, original_text, previous_quote_id, next_quote_id, content_sha256`。

- 完整原文保持不变，摘要另存为 `abstract`。没有可靠说话人姓名时保留原角色，不猜姓名。
- 原始来源的时间字符串及其时区语义原样保留；用户显示时区不能回填成数据发生地时区。
- 一条消息只能有一个规范引文，可被多个节点引用；L2–L5 保存传递的引文/事件 ID。去重不能导致不同发言被删除。
- 构建后校验原始 ID 全覆盖、文本哈希一致、邻接次序一致、无跨对话引用；运行时只读持久化 L1 原文表，不再读取外部 L0 文件。
- 这是 L1 存储内容变更，报告明确说明；不能称为原摘要自然恢复了细节。

### 8.2 事件级时间绑定

在保存的原文内提取事件提及和时间短语，以 `source_id + span` 绑定具体出现位置。若一句含多个事件或多个同样短语，只有事件关系可明确时才绑定；不确定保留 `ambiguous`，不把注释套给整个节点。

W0 的观察时间、事件时间、粒度和相对周规则继续区分：

- “上周”保留周级信息；“上周末”保留周末表达；不知道具体哪天就不产生某日。
- 计划、愿望、邀请与已发生事件分开；同一活动先计划后完成可以有状态转移，不能覆盖旧记录。
- 父节点窗口不参与事件日期换算。最早观察到、第一次提到、第一次发生是不同字段/关系。
- 明确日期、相对日期、持续时长和未知时间分别存储；只对已有 W0 解析器支持且来源明确的表达生成对应注释。扩展时间解析规则另做消融。

### 8.3 角色/别名和证据组的保真升级

从发言者元数据、原文称呼和相邻问答中建立有来源的实体别名。L1/L2 与五层组共用实体索引，单独比较“有/无公共别名”的开发消融，避免把人物名补全造成的收益算成高层组织优势。

上下文切换为原始引文邻接与显式指代/回复关系。只保存真实原文边界；为了候选预算而显示片段时必须保留原文偏移和检索完整原文的 ID，不改写片段来适配题目。

### 8.4 新对照与日期路由

新目录建议 `F:/codex数据库memory/locomo_hierarchy_relevance_r2_quotes_20261024`。

- `Q-L`：保真 L1/L2 + 公共实体/事件索引 + 统一语义筛选。
- `Q-H`：同一保真低层库、相同筛选预算 + L3–L5 规范导航。
- 直接日期路由先保持 R1 的保护设置，在开发阶段增加一个明确的 `direct_time_navigation` 开关消融；只有事件身份和时间引用均有原文支持时才允许高层改变日期题证据。

日期题不是简单打开高层即完成：应确认候选回答的是同一事件、是否完成、所需粒度及相对时间锚点；匹配不确定就回退低层。对于列表、比较、时间关系题，需要有来源的多个事件，不要求它们属于同一次事件。

最终正式比较仍用同一冻结配置的 Q-H−Q-L，两组都使用相同日期开关语义和筛选过程，区别仅在高层候选可达性。如果保留开关关闭/开启两组作正式消融，提前增加实验组并冻结，不在看到主结果后临时挑选更高一组报告。

Q-L 相对旧摘要低层的变化同时包含原文保真、上下文及索引修改；若未单独控制这些因素，只能报告整套表示变更的效果。R2 的正式测试遵循 R1 的冻结、两次配对、独立缓存和报告要求。

## 9. 评测与验收：分数之外必须交付什么

### 9.1 硬性正确性条件

- 861 题完整，类别分母与题目集合一致，错误请求未被静默排除；保存失败及重试数量。
- 无跨对话来源、无伪造引用/区间、无无支持高层文字直接充当底层事实。
- 同源重复不计多次独立支持；上下文顺序与去重规则明确。
- 存储构建不读问题；运行时检索/语义筛选不读 gold、类别和历史判分。
- 模型、提示、格式化器、窗口数与预算对照一致；真实模型返回名与用量落盘。
- 相同完整输入仅在同一重复批次内共享响应；开发、正式和重复批次响应隔离。
- 不改变主判分器的既有标签以追求更好的表格。

### 9.2 相关性与失败分解

报告每层命中路径、规范候选数、最终被接受组数、输入真正改变题数、逐字回退率及拒绝原因。多层标签的同一证据只计一个来源组。

对固定、隐藏组别的抽查样本报告：来源支持率、所问事件/关系匹配率、新槽位或新关系覆盖、无关上下文比例、必要低层证据被替换的次数。人工审计样本量和抽样方式必须列出，不能将审计比例冒充全量真值。

正式完成后才进行错误诊断，按下列层次区分：

1. 所需事实在记忆库中不存在或被摘要损坏。
2. 库中存在，但候选生成未召回。
3. 候选中存在，但筛选或截断丢掉。
4. 正确支持已在最终证据中，答题仍选择错误事件或范围。
5. 回答语义近似但判分不一致，或者审计无法确定。

只有有来源标注或人工核验时才报告“答案支持召回率”；无法完整标注时报告抽样诊断，不用答案字符串匹配代替语义召回真值。正式金标准只允许用于评分和事后诊断，不能回流当轮路由。

### 9.3 主成绩、复测与判分一致性

- 每次重复分别列出时间、单跳、多跳、推理和总体的正确数/分母、准确率、差值。
- 列出配对修复、退步、各对话净变化、两次同向与反向案例；报告精确 McNemar 作为辅助量。
- 同一问题的两次重复不能当作新增独立问题合并检验。若给出平均准确率，明确它是相同 861 题的重复均值。
- 可做按对话聚类的配对置信区间作为敏感性分析；只有 10 段对话，说明不确定性，不能只凭题级 p 值宣称泛化。
- 主表保留预注册判分结果。另将两臂不一致、同答案异标签及近义答案的固定审计集合去除组名、历史标签和执行顺序，做对称盲审；审计结论独立保存，不能只重判不利于 H 的题。
- 新开发样本、旧 40 题、本文诊断题等取并集，另报告其补集成绩与实际分母；这仍属于旧 LoCoMo 的开发外结果，不称未见测试集。有新会话才另外报告独立验证。

### 9.4 推荐验收标准

以下为下一轮开始前可固定的研究推进标准，不是已达成指标，也不承诺准确率必升：

1. 所有硬性条件通过，失败请求清零或按冻结协议明确记为失败。
2. H 相对同轮 L 在两次完整重复中总体均为正向；不以单次净增几题宣布稳定优势。
3. 时间、单跳、多跳、推理每类的两次平均净差不为负，并逐次公开负差；小类别分母小，需要同时看题数和审计。此规则是谨慎的工程推进门槛，不是统计学非劣效证明。
4. 对“相关性变好”的解释必须有候选/证据组审计支持；若只改善回答措辞或判分结果，不声称检索机制得到验证。
5. 若要宣称“稳定优于”或推广到新数据，还需要足够的不确定性分析和未参与开发的会话验证。只满足上述工程门槛时，结论为“值得进入下一轮验证”。

用户希望保持其他类表现，因此不预设用单跳下降换取时间上涨的成功标准。若只出现这种权衡，完整报告，保留低层回退方案，不把它升级为默认方案。
