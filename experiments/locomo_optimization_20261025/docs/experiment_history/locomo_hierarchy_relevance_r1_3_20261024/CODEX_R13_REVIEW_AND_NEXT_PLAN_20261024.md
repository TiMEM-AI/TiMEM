## 3. 三个必须补正的实现点

### 3.1 真实 B 没有进入模型，不能判断替换损失

当前 `stage_b.py` 发送：

- protected：每个窗口只发第一个 `fact_id`，没有正文。
- tail：只发每个尾部窗口第一条事实的前 160 字符。
- optional：只发中心正文，缺观察时间和邻接上下文；没有可解析的实际 fact_id 映射。

模型无法由不透明的哈希 ID 判断前 20 窗口已覆盖什么，也无法知道尾部其余事实是否重要。因此 `lost_query_support=[]` 不是无损证据，模型返回若干 supporting_fact_ids 也尚未完成来源校验。

实际这批 protected 含 95–118 条事实，却只给模型 20 个 ID；尾部含 14–21 条事实，却只给 4 段截短首事实。11 个 valid 响应中 5 个 decisions 集合不完整，112 条 evidence_decisions 的 supporting_fact_ids 全为空。这里的 valid 首先是传输/解析状态，不等价于已经通过选择计划的支持契约。

**最小修正：统一序列化同一个窗口对象。**

```text
window_id / 短标签
kind: protected | tail | optional（来源层级隐藏）
conv_scope
observed_at
center_fact_label
facts: [{fact_label, actual_fact_id, full_text}]
必要的原时间注释或事件时间字段
```

可用短标签减少输出负担，但程序必须保存短标签到真实 ID 的一一映射。B 的真实事实顺序、完整正文、时间及相关 W0 注释都应可见；不能把 ID 清单称为“已经发送完整 B”。

候选使用 legacy 中心附近原子窗口，保留必要指代/问答关系。不要调用当前按同日遍历取前几条的 `atomic()` 代替语境；它目前也没有接入阶段 B 的实际候选呈现。

筛选总输入上限沿用 24,000 token、输出上限 4,096 token 作为初始配置。先保留完整 B，再按共同规则减少完整可选组；B 自身超限则回退并记录，不默默裁掉 B 或候选中心。这里的 token 与字符数分开统计。

### 3.2 `seen` 的作用域不对，高层排序也仍未实现

当前 `build_pool()` 在扫描低层全库时，把所有带任意查询词的 B 外事实加入 `seen`，随后上层排除 `seen`。这排除的不仅是最终低层前 8 个，也包括没有被选入低层池的后续事实。

结果是：一个高层目标只要在正文里有查询词，就可能在被高层取到之前被全局 `seen` 排除。剩下的高层候选在当前代码中被迫没有查询词重合；这不是语义检索的结果，也不是合理的两通道去重。

上层还按 `route_id` 排序，而非相关性分数，最多取 4 个就停止。哈希排序只提供确定性，不提供问题相关性。

**按以下顺序修复，不改变事实库：**

1. L 从现有低层 BM25 检索生成完整有序候选流，按 legacy 原子窗口规范化。
2. H 先放前 8 个唯一低层可选窗口。这里的 seen 只包含 B 已呈现支持及 H 已选入的窗口，不包含整个低层检索结果。
3. 对折叠路由先做相关性排序，再从 top-200 有序展开目标，跳过真正已经呈现/占槽的重复，取至多 4 个高层发现窗口。不能先按哈希取几个。
4. 高层候选可以来自低层检索的较后位置；同一事实库内的这种可达性改善正是实验目标，不应预先禁止。
5. H 不足 12 个可选窗口时用后续低层窗口补齐，候选不足则公开实际数量，不伪造填满。L 取至多 12 个低层窗口。
6. 相同候选集合使用相同展示顺序和标签，完全相同提示共享响应；来源路径只在审计元数据保留。

每题记录 B 覆盖、L 候选、H 公共候选、H 独有候选、最终选入及其来源。由低层公共候选引起的变化不能记为“上层新事实补召回”。

### 3.3 模型输出必须经过程序验证和原子应用

当前阶段 B 直接读两个 ID 数组，先删除尾部再追加，最后 `chosen[:24]`。没有完整校验未知 ID、重复、支持引用、约束冲突、丢失支持或预算；使用 set 遍历还可能使多选情况下的顺序不稳定。

R1.3b 的主实验先采用**交换式增补**，将“精简 B”从本次高层效应中隔离：

- 保护前 20 个窗口完全保留。
- B 满 24 时，接受 n 个可选窗口必须移除 n 个合法尾部窗口，n≤4；不接受 selected=0、removed>0。
- B 不满时优先用空位；需要额外替换时只替换实际存在的可替换尾部。拒绝无效或超额操作，不靠静默截断修正。
- 每个选入必须有合法来源、可核验的问题支持说明；约束冲突、未知引用或声明丢失必要支持时整次计划回退 B。
- 对 supporting_fact_ids/短标签验证确实属于所指窗口，不能把 c1、t1 当作未映射的真实事实 ID。
- 模型对问题相关性的判断仍可能错误；程序校验不冒充语义正确性证明。对全部实际交换逐项语义复核，见第 5 节。
- 先模拟最终窗口、全局去重和预算，再一次性提交；若去重导致空窗、关键支持丢失或数量约束不满足，恢复 B。
- 最终呈现按固定顺序，所有已选支持实际出现在最终字符串中，W0 格式/观察时间/注释保持一致。

纯删除可能有价值，但应作为独立的“低层精简”实验。本轮不把它混在高层候选收益中，先把交换实验做清楚。

保留原文件，增加 `audit_method=lexical_prefill` 或独立状态说明。**不要再编写一个词面规则脚本，把命中结果改名成语义完成。**

| 正确支持已在 B，但主要错在时间计算/组合/答案表述 | 做统一答题或证据组织的独立实验，明确与高层导航分离 |
| 两臂始终同输入或没有可信新增支持 | 工程上封存“当前配置没有形成可测增益”；不运行两份相同全量，也不推出所有高层方法无效 |

若扩测，预先固定重复次数、配对方法和每类报告，不根据正式分数再调规则。当前所有题集都已用于本项目开发，不能称全新独立测试；若要泛化结论，另补未参与开发的会话验证。
