# L3–L5 的 W0 时间存储与证据格式改造

本批次只修改本地快照，不写入太忆空间。继续使用 deepseek-v4.1-flash 答题和判分。

## 先纠正比较口径

原 W0 的实现位于召回后的证据渲染层，并没有原位重写 L1/L2 数据库。它从召回证据对应的原始观察中解析时间，再追加独立的日历注释。

上一轮 `locomo_space_l1_l5_20261024/run_full.py` 把 8,000 字符误当成了全部证据的上限。实际 W0 的 8,000 字符只限制新增注释；主证据由 `bench/evaluators/aml_score.py::format_memories` 计算 token 预算（117,760，另扣查询长度）。上一轮 62.95% 的下降混入了这一错误，不能据此断言高层记忆无效。

## 存储修改

- 671 个 L1/L2 节点完整保留原 JSON 内容。
- 565 个 L3/L4/L5 节点保存为 `upper-w0-fact-time-v2`。
- `window` 单独存放汇总起止时间，只表示聚合范围，不再充当所有事实的时间。
- `fact_units[]` 保留现有高层事实原句，以及该事实自己的 `observed_at`。只有标记能在同一节点后代的真实观察时间集合中验证时才接受，绝不回退到父节点窗口。
- `annotations[]` 保存 W0 的短语、原始来源 ID、原文字符区间、观察时间、粒度、日历值或相对周锚点，以及 W0 原格式注释行。
- 原始对话仅在构建阶段用于验证时间短语及时间，不复制成新的原文事实。测试阶段只读取已经保存的记忆和注释，不读取 L0 SQLite。
- 短语绑定要求整词匹配并优先最长短语，避免把 `last week` 匹配进 `last weekend`，或把 `yesterday` 匹配进 `day before yesterday`。
- 同一观察时间和相同短语足以核验日历换算，但未宣称能唯一确定原文中的事件对应关系；这一限制保存在每条绑定的元数据中。

本批保留高层现有事实文字，没有再次调用模型生成摘要。因此无法恢复此前摘要已经丢失的事实。

## 召回与渲染

BM25 的索引文字、参数、对话隔离、排序以及最多 12 个内容去重节点的选择不变。对全部 861 题重新复现上一轮的检索和旧打包过程，旧证据文本逐字比对无差异。新时间注释不参与 BM25 打分。

L3–L5 命中后按事实自己的观察时间拆成证据行，正文明确标记为 `Derived memory summary:`，不把改写的摘要伪装成原始对话。不同高层节点中完全相同的日期和事实文字去重。

继续复用冻结 W0 的日期查询路由、日/月/年换算器和周表达锚定器，只对其识别的日期问题呈现注释。周与周末保留相对表达，例如 `the week before March 27, 2023`，不输出 W1 的日期范围。注释区标题与各字段格式沿用 W0。

注释先 C1（日/月/年）、后 W0（周/周末），总新增预算为 8,000 字符；主证据恢复 W0 的官方 token 格式化函数。答题和判分模板文件哈希也与原 W0 实验一致。

“格式一致”指相同的格式化函数、时间字段语义、粒度和注释区约定；正文仍是本地 L1–L5 的派生记忆，原 W0 的正文则包含原始对话。当前实验也没有恢复原 W0 的原始对话检索通道。

## 验证与实验分组

固定 40 题 smoke，每类 10 题，种子 20261024。时间题有意覆盖已存储的日历与周注释；选题不使用答案或历史正确性。题目一经固定不随结果改变。

1. `budget_control`：仅恢复 W0 主证据预算，保留旧存储和旧窗口呈现，用于观察预算修正的作用。
2. `upper_w0`：同一候选排序和预算，加上本次上层存储与时间呈现。

初版 smoke 后的静态检查发现短语子串边界问题，已归档到 `smoke_v1_boundary_bug/`；修正后使用相同 40 题复跑。未根据答案或分数选取版本。

smoke 的全量门槛是请求完成、模型配置一致、来源与格式审计通过，不根据小样本分数挑题或挑方案。通过后 `upper_w0` 另跑 861 题，重新答题和判分，不复用 smoke 的模型响应。

全量对比包括上一轮 62.95% 和原 W0 的 84.67%。本轮同时修正了证据预算并改造上层表示；40 题对照可提供线索，但没有预算对照组的全量成绩，不能精确拆分两项修改的全量贡献。

## 主要文件

- `memories.json`：改造后的实际存储。
- `storage_audit.json`：L1/L2 不变、来源与事实观察时间检查。
- `format_audit.json`：861 题检索复现及 W0 格式检查。
- `requests/`：实际喂给答题模型的证据及来源注释。
- `smoke_selection.json`、`smoke_summary.json`：固定选题和最终 smoke 结果。
- `full/upper_w0/rows/`：逐题模型输出、请求哈希、用量、判分与证据文件链接。
- `upper_w0.py`、`run_eval.py`：构建、渲染和断点续跑脚本。
